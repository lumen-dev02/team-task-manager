# REST API

Базовый путь: `/api/v1`. Тела запросов и ответов — JSON, кроме ответов `204 No Content`. Для запросов с телом обязателен `Content-Type: application/json`. Лимит тела — 1 MiB, неизвестные поля и несколько JSON-значений в одном теле отклоняются.

Все маршруты, кроме регистрации, входа и health checks, требуют `Authorization: Bearer <access_token>`. Даты возвращаются в RFC 3339. ID — положительные `int64`; клиентам JavaScript следует учитывать ограничение точности `Number` для больших ID.

## Маршруты и права

| Метод | Путь | Доступ | Успех |
| --- | --- | --- | --- |
| POST | `/auth/register` | Все | 201, пользователь |
| POST | `/auth/login` | Все | 200, токен |
| GET | `/me` | Авторизованный пользователь | 200, пользователь |
| POST | `/projects` | Авторизованный пользователь | 201, проект |
| GET | `/projects` | Авторизованный пользователь, только свои проекты | 200, массив |
| GET | `/projects/{projectID}` | Участник | 200, проект |
| DELETE | `/projects/{projectID}` | Владелец | 204 |
| GET | `/projects/{projectID}/members` | Участник | 200, массив |
| POST | `/projects/{projectID}/members` | Владелец | 204 |
| DELETE | `/projects/{projectID}/members/{memberID}` | Владелец | 204 |
| POST | `/projects/{projectID}/tasks` | Участник | 201, задача |
| GET | `/projects/{projectID}/tasks` | Участник | 200, массив |
| GET | `/projects/{projectID}/tasks/{taskID}` | Участник | 200, задача |
| PUT | `/projects/{projectID}/tasks/{taskID}` | Участник | 200, задача |
| DELETE | `/projects/{projectID}/tasks/{taskID}` | Участник | 204 |
| GET | `/projects/{projectID}/tasks/{taskID}/history` | Участник | 200, массив |

Владелец автоматически входит в состав участников. Все участники могут редактировать и удалять любые задачи своего проекта, не только созданные ими. Если пользователь не участник, API возвращает `404`, не раскрывая наличие проекта. Участник, пытающийся управлять составом команды или удалить проект, получает `403`.

## Пользователи

Регистрация:

```json
{"email":"timur@example.com","name":"Timur","password":"local-demo-password"}
```

Email обрезается по краям и приводится к нижнему регистру; адреса с отображаемым именем не принимаются. Длина — до 254 байт. Имя — 1–80 символов после обрезки пробелов. Пароль — 12–72 **байта** (ограничение bcrypt), без автоматической обрезки пробелов. Повторный email — `409`.

Ответ регистрации и `/me`:

```json
{"id":1,"email":"timur@example.com","name":"Timur","created_at":"2026-11-07T12:00:00Z"}
```

Вход принимает `email` и `password`. Ошибка существующего и несуществующего аккаунта одинакова: `401 invalid_credentials`.

```json
{"access_token":"<signed-jwt>","token_type":"Bearer","expires_in":3600}
```

Токен HS256 проверяется по алгоритму, подписи, issuer, audience, subject и сроку действия. Обновления токена нет — после истечения нужно войти заново. На регистрацию и вход действует общий лимит процесса: 2 запроса/с, burst 5; превышение даёт `429` с `Retry-After: 1`.

## Проекты и участники

Создание проекта:

```json
{"name":"Course project","description":"Team planning"}
```

Имя — 1–120 символов, описание — до 4000. Описание необязательно, по умолчанию `""`. Ответ содержит `id`, `name`, `description`, `owner_id`, `created_at`. Редактирование проекта и передача владения в текущий API не входят.

Добавление зарегистрированного пользователя в участники:

```json
{"email":"member@example.com"}
```

Несуществующий email — `404`, повторное добавление — `409`. Подтверждение приглашения не реализовано. Владелец не может удалить себя (`400`). При удалении участника API в одной транзакции снимает его со всех задач проекта и увеличивает версии этих задач.

Список участников:

```json
[{"user_id":1,"name":"Timur","role":"owner"},{"user_id":2,"name":"Member","role":"member"}]
```

Email участников в этом ответе не возвращается. Список участников пока без пагинации.

## Задачи

Создание (статус всегда `todo`, версия `1`):

```json
{"title":"Implement task filters","description":"Filter by status and assignee","assignee_id":2}
```

`title` — 1–200 символов, `description` — до 10000. `description` и `assignee_id` необязательны; по умолчанию `""` и `null`. Исполнитель должен состоять в проекте, иначе `400`. Поля `status` и `version` при создании не принимаются.

Пример ответа (значения иллюстративные):

```json
{
  "id":10,
  "project_id":1,
  "title":"Implement task filters",
  "description":"Filter by status and assignee",
  "status":"todo",
  "assignee_id":2,
  "created_by":1,
  "version":1,
  "created_at":"2026-11-07T12:00:00Z",
  "updated_at":"2026-11-07T12:00:00Z"
}
```

### Обновление

`PUT` заменяет редактируемое состояние целиком:

```json
{"title":"Implement task filters","description":"Covered by tests","status":"done","assignee_id":null,"version":1}
```

- Требуются `title`, `status` и текущая `version`. Пропущенное описание становится `""`, пропущенный исполнитель — `null`.
- Допустимые статусы: `todo`, `in_progress`, `done`. Разрешён переход между любыми из них, включая повторное открытие завершённой задачи.
- Каждое успешное обновление увеличивает `version`, даже если значения не изменились.
- При несовпадении версии — `409`, без изменений задачи и истории. Клиенту нужно перечитать задачу и согласовать правки, а не слепо повторять запрос.
- История пополняется только при смене статуса; создание записывается как переход из `null` в `todo`.
- Удаление задачи не использует версию; эта операция безусловна после проверки прав.

### Списки и история

```text
GET /api/v1/projects/1/tasks?status=in_progress&assignee_id=2&limit=20&offset=0
GET /api/v1/projects/1/tasks/10/history?limit=20&offset=0
GET /api/v1/projects?limit=20&offset=0
```

`limit` по умолчанию 20, диапазон 1–100. `offset` по умолчанию 0, диапазон 0–1000000. Фильтры задач необязательны и объединяются через AND. Выборка только неназначенных задач не реализована. Порядок списков — по возрастанию ID; при конкурентном добавлении и удалении offset-пагинация не гарантирует неизменный снимок. Пустой результат — `[]`.

История:

```json
[
  {"id":1,"from_status":null,"to_status":"todo","changed_by":1,"changed_at":"2026-11-07T12:00:00Z"},
  {"id":2,"from_status":"todo","to_status":"done","changed_by":2,"changed_at":"2026-11-07T13:00:00Z"}
]
```

История не содержит изменения описаний и назначений. После удаления задачи история недоступна и удаляется каскадно.

## Ошибки

Обработчики API возвращают:

```json
{"error":{"code":"conflict","message":"Resource already exists or task version is outdated"}}
```

| HTTP | Причина |
| --- | --- |
| 400 | Невалидные поля, ID, параметры, JSON, исполнитель вне проекта, удаление владельца |
| 401 | Нет токена, токен недействителен или неверные данные входа |
| 403 | Участнику не хватает прав владельца |
| 404 | Ресурс не существует либо недоступен пользователю |
| 409 | Повторный email/участник или устаревшая версия задачи |
| 413 | Тело больше 1 MiB |
| 415 | Неверный Content-Type |
| 429 | Превышен лимит входа/регистрации |
| 500 | Внутренняя ошибка без деталей SQL в ответе |
| 503 | Таймаут запроса или недоступность БД в readiness |

В ответах есть `X-Request-ID`, который также пишется в структурированный лог. Несуществующий маршрут или неподдерживаемый HTTP-метод обрабатывает стандартный `http.ServeMux`: его ответы `404`/`405` текстовые, не JSON. Клиенту не следует предполагать JSON для любого сетевого ответа.

## Проверки состояния

Маршруты без префикса `/api/v1`, без авторизации:

- `GET /healthz` — процесс отвечает: `200 {"status":"ok"}`.
- `GET /readyz` — PostgreSQL отвечает на ping в течение секунды: `200`, иначе `503`. Это не проверка версии схемы; миграция запускается отдельно перед API.
